# Markdown 格式规范

## 描述

本 Skill 定义了 Markdown 文件的标准格式规范。在创建或编辑任何 `.md` 文件时，必须遵循以下规则，以确保文档结构清晰、排版统一、跨平台兼容。

**触发条件**：处理 Markdown 文件（创建、编辑、重构、格式化）时自动生效。

---

## 1. 基础结构规范

### 1.1 文件编码
- 统一使用 **UTF-8** 编码，带 BOM 或不带 BOM 均可，但建议不带 BOM。
- 使用 **LF**（`\n`）作为换行符，避免混用 CRLF。

### 1.2 标题层级
- **文档正文从 H2 开始**，不单独书写 H1。文件名即为文档的隐式 H1。
- 标题层级必须**连续**，禁止跳级（如 H2 后直接接 H4）。
- 标题前后必须各保留**一个空行**（文件开头除外）。
- 标题语法统一使用 `#` 前缀，不使用下划线等效写法。

```markdown
<!-- ✅ 正确 -->
文件名：文档标题.md

## 第一节

### 1.1 小节

## 第二节

<!-- ❌ 错误 -->
# 文档标题

### 直接跳到三级标题

## 第二节
```

## 2. 段落与空行

- **段落之间**必须用一个空行分隔。
- **块级元素之间**（标题、列表、代码块、引用块、表格）必须用一个空行分隔。
- 段内禁止随意换行，除非是有意断句。一句话应在同一行内写完。
- 禁止使用连续三个及以上的空行。

```markdown
<!-- ✅ 正确 -->
这是第一段内容。同一句话保持在同一行内，不要中途换行。

这是第二段内容。

## 新标题

<!-- ❌ 错误 -->
这是第一段。
这里不该换行却换了。



连续多个空行是多余的。
```

---

## 3. 列表规范

### 3.1 无序列表
- 统一使用 `-`（短横线）作为列表标记，不使用 `*` 或 `+`。
- 列表标记后必须跟一个空格。
- 嵌套列表缩进 **2 个空格**。
- 列表项末尾不加标点（句号、分号等），除非该项是完整段落且包含多句话。

```markdown
<!-- ✅ 正确 -->
- 列表项一
- 列表项二
  - 嵌套项 A
  - 嵌套项 B
- 列表项三

<!-- ❌ 错误 -->
* 不要用星号
+ 不要用加号
-  不要两个空格
-列表标记后缺少空格。
```

### 3.2 有序列表
- 使用 `1.`、`2.`、`3.` 的顺序编号，不推荐使用反向编号或全部用 `1.`。
- 编号后必须跟一个空格。
- 嵌套缩进同样为 **2 个空格**。

```markdown
<!-- ✅ 正确 -->
1. 第一步
2. 第二步
   - 子步骤 A
   - 子步骤 B
3. 第三步
```

### 3.3 任务列表
- 统一语法：`- [ ]` 未勾选，`- [x]` 已勾选（注意 `x` 为小写）。
- 方括号内两侧各有一个空格。

```markdown
- [ ] 待办事项一
- [x] 已完成事项
```

## 4. 代码块

- **必须指定语言标识符**（如 ` ```python `、` ```bash `、` ```json `），不使用纯 ` ``` `。
- 代码块前后必须各有一个空行。
- 代码块内部保持原始格式，不做额外缩进。
- 行内代码使用单个反引号 `` ` ``，反引号前后不加多余空格。

```markdown
<!-- ✅ 正确 -->
以下是 Python 示例：

```python
def hello():
    print("Hello, World!")
```

使用 `print()` 函数输出内容。

<!-- ❌ 错误 -->
以下是 Python 示例：
```
def hello():
    print("Hello")
```
使用 ` print() ` 输出。（反引号两侧多余空格）
```

## 5. 链接与图片

### 5.1 链接
- 优先使用标准 Markdown 内联链接：`[显示文本](URL)`。
- **Obsidian 内部链接**：在 Obsidian 库内引用其他笔记（如每日汇总中链接单篇文章）时，使用 wiki 链接格式：
  - 基础形式：`[[文件名]]`
  - 带自定义显示文本：`[[文件名|显示文本]]`
- 链接文本应具有描述性，避免使用"点击这里"、"这里"等无意义文本。
- 当同一链接多次出现时，可使用引用式链接（reference-style）。
- 外部 URL 使用 HTTPS 协议，除非目标仅支持 HTTP。

```markdown
<!-- ✅ 正确 -->
详情请参阅 [Google 搜索](https://www.google.com)。

[obsidian]: https://obsidian.md "Obsidian 官网"

<!-- ❌ 错误 -->
点击[这里](https://www.google.com)。
```

**Obsidian 每日汇总示例**（注：本项目归档管线已改为输出 HTML，不再生成此类 Markdown 汇总；以下仅作 Markdown + Obsidian 语法的通用参考）：

```markdown
<!-- ✅ 正确 -->
本文件汇总了当日收录的 33 篇文章，按来源分类整理，简要说明每篇文章的核心内容。

## 一、seangoedecke.com RSS feed（2 篇）

### [[「seangoedecke.com RSS feed」DeepSeek-V4-Flash means LLM steering is interesting again|DeepSeek-V4-Flash means LLM steering is interesting again]]

探讨了 **LLM Steering（模型导向/操控）** 技术的现状与前景。随着 DeepSeek-V4-Flash 等本地可运行模型的成熟，Steering 从实验室走向工程师可实践的阶段。

### [[「seangoedecke.com RSS feed」How I use LLMs as a staff engineer in 2026 |How I use LLMs as a staff engineer in 2026]]

作者（一名 staff engineer）分享了自己在 2026 年使用 LLM 的方式变化。核心变化是 **Agents 已经非常强大**。
```

### 5.2 图片
- 使用标准 Markdown 语法：`![alt 文本](图片URL)`。
- alt 文本为可选项；如有则应当描述图片内容，无则留空。
- 避免使用 HTML `<img>` 标签，除非需要控制尺寸（此时应在备注中说明）。
- 图片前后应有一个空行（作为独立块级元素）。

```markdown
<!-- ✅ 正确 -->
![青海湖日落](https://example.com/qinghai-lake.jpg)

![](https://example.com/img.jpg)

<!-- ❌ 错误 -->
<img src="https://example.com/img.jpg" width="300">
```

## 6. 表格

- 使用标准的 Markdown 表格语法（GFM 风格）。
- 表头与内容之间使用分隔行 `|---|---|`，对齐方式统一使用左对齐（`|:---|`）或默认（`|---|`），不混用。
- 每列的 `|` 两侧各有一个空格，提升可读性。
- 表格前后应有一个空行。

```markdown
<!-- ✅ 正确 -->
| 功能 | 描述 | 状态 |
|------|------|------|
| 登录 | 用户认证入口 | 已完成 |
| 注册 | 新用户注册 | 开发中 |

<!-- ❌ 错误 -->
|功能|描述|状态|
|---|---|---|
|登录|用户认证入口|已完成|
```

## 7. 引用块

- 使用 `>` 作为引用标记，每行开头都有 `>`（或段落首行）。
- `>` 后紧跟一个空格。
- 引用块前后应有空行。
- 引用块内可以嵌套其他 Markdown 元素（如列表、代码块）。

```markdown
<!-- ✅ 正确 -->
> 这是一段引用内容。
>
> 引用可以包含多段。

<!-- ❌ 错误 -->
>没有空格
>  两个空格过多
```

## 8. 强调与格式化

- **加粗**：使用双星号 `**文本**`，不使用双下划线 `__文本__`。
- *斜体*：使用单星号 `*文本*`，不使用单下划线 `_文本_`。
- 加粗和斜体标记内侧**不紧贴**标点符号，但**紧贴**文字。
- `***加粗且斜体***` 仅在必要时使用。
- 删除线使用双波浪线 `~~文本~~`。

### 8.1 引号规范
- **中文内容优先使用直角引号**：外层用「」，内层用『』。
- **避免使用弯引号** `""` 和 `''`，避免中英文引号混用。
- 英文内容仍使用标准英文直引号 `"` 和 `'`。

```markdown
<!-- ✅ 正确 -->
这是**加粗**文字，这是*斜体*文字。

「只说 No 的工程师」会灭绝吗？

他说：「我记得她讲过『数据主权』这个概念。」

The engineer said, "This is a 'just-say-no' archetype."

<!-- ❌ 错误 -->
这是 ** 加粗 ** 文字。（标记内侧多余空格）
这是__加粗__文字。（使用了下划线）

"只说 No 的工程师"会灭绝吗？（使用了弯引号）
```

---

## 9. 水平分隔线

- 使用三个短横线 `---` 独占一行。
- 分隔线前后应有空行。
- 不使用 `***` 或 `___`。

```markdown
<!-- ✅ 正确 -->
内容段落 A。

---

内容段落 B。
```

---

## 10. 中英文混排规范

- **中文与英文/数字之间**必须加一个空格。
- **中文与中文标点之间**不加空格。
- **英文/数字与英文标点之间**不加空格。
- 专有名词保持原有大小写（如 iPhone、macOS、Obsidian）。
- 使用中文标点（，。！？：；""''）处理中文内容，英文内容使用英文标点。

```markdown
<!-- ✅ 正确 -->
在 Python 3.12 中，asyncio 模块有了显著提升。

今天是 2026 年 5 月 19 日，气温 25°C。

<!-- ❌ 错误 -->
在Python3.12中，asyncio模块有了显著提升。（缺少空格）
在 Python 3.12 中 ， asyncio 模块有了显著提升。（标点前后多余空格）
```

## 11. HTML 标签使用限制

> **适用范围注记**：本规范面向项目中的 `.md` 文档（如 `doc/`、`skills/`）。归档管线自改造后**不再产出 Markdown**，而是输出干净 HTML（见 `src/core/render_html.py`、`doc/render_html.md`），其产物不受本节「避免嵌入 HTML」约束。

- **优先使用纯 Markdown 语法**，避免嵌入 HTML。
- 仅在以下情况允许使用 HTML：
  - 需要 `<details>` / `<summary>` 实现可折叠内容。
  - 需要 `<kbd>` 标注键盘按键（如 `<kbd>Ctrl</kbd> + <kbd>C</kbd>`）。
  - 平台强制要求（如某些表格合并单元格需求）。
- HTML 标签内的内容同样遵循中英文混排规范。

## 12. 双语文档规范

当文档同时包含中英文内容（如翻译稿、中英对照）时，遵循以下附加规则。

### 12.1 双语标题

- **禁止将同一标题的中英版本写成两个独立的 Markdown 标题**（如 `# Title` 后紧跟 `# 标题`）。
- 应使用单个 HTML heading 标签包裹，两种语言之间用 `<br>` 换行，确保大纲/目录中只生成一个条目。
- 正文标题级别仍从 `<h2>` 开始。

```markdown
<!-- ✅ 正确 -->
<h2>The end of ZIRP<br>ZIRP 的终结</h2>

<h3>AI<br>人工智能</h3>

<!-- ❌ 错误 -->
## The end of ZIRP

## ZIRP 的终结

### AI

### 人工智能
```

### 12.2 段落间隔

- **一段英文与其对应的中文翻译之间必须有一个空行**，不要直接紧接在下一行。
- 即排版顺序为：英文段落 → 空行 → 中文段落 → 空行 → 下一段英文。

```markdown
<!-- ✅ 正确 -->
The just-say-no engineer is having a hard time in the era of AI.

在 AI 时代，"只说No的工程师"正举步维艰。

It used to be that they only had to say no to more junior engineers' handwritten PRs.

过去他们只需要对初级工程师手写提交的 PR 说"不"。

<!-- ❌ 错误 -->
The just-say-no engineer is having a hard time in the era of AI.
在 AI 时代，"只说No的工程师"正举步维艰。
It used to be that they only had to say no to more junior engineers' handwritten PRs.
过去他们只需要对初级工程师手写提交的 PR 说"不"。
```

## 13. 附录：快速检查清单

在处理完任何 Markdown 文件后，按以下清单自检：

- [ ] 文档正文从 H2 开始，无显式 H1（文件名即为 H1）。
- [ ] 标题层级连续，无跳级。
- [ ] 块级元素之间有空行。
- [ ] 无序列表统一使用 `-`。
- [ ] 代码块指定了语言标识。
- [ ] 图片使用标准 Markdown 语法。
- [ ] 链接文本具有描述性。
- [ ] 中英文/数字之间加了空格。
- [ ] 中文内容使用直角引号「」而非弯引号 ""。
- [ ] 没有使用无意义的 HTML 标签。
- [ ] 无连续空行，无尾随空格。
- [ ] 无 YAML Front Matter。
- [ ] 双语文档的英文标题用 Markdown 语法，中文标题用 HTML 标签。
- [ ] 双语文档中英文段落与中文段落之间有空行。
